# Automatic adapter generation

`app2cli generate` runs an actual coding agent, not a lookup table of bundled adapters. The initial inputs are an application URL or APK, an output directory, and optionally a description of the capability. The runner invokes REA, gives the agent the captured source and live UI observations, compiles the returned adapter, and executes a bounded real-application acceptance scenario. Test failures become the next agent prompt.

## Run from a URL

Install dependencies as described in the README. Install Codex CLI and complete `codex login` using your own account. The runner uses the configured Codex model; it does not copy credentials or change global configuration. See the [official non-interactive documentation](https://developers.openai.com/codex/noninteractive/) for `codex exec`.

```bash
node bin/app2cli.mjs generate https://dillinger.io/ \
  --id dillinger --out .local/generate/dillinger \
  --goal "Read and replace the current Markdown document; verify the preview after reload"
```

Without `--cdp`/`APP2CLI_CDP`, the runner launches Chrome with a fresh profile under the run directory and an automatically selected loopback CDP port. Set `APP2CLI_CHROME` if Chrome is installed elsewhere, `APP2CLI_PROXY` if the browser needs an HTTP proxy, or pass `--headed` to show the window. It leaves this browser available for the generated CLI. Close that dedicated Chrome instance when finished.

For an authenticated application, log in yourself in a dedicated Chrome instance and supply `--cdp http://127.0.0.1:PORT --target TARGET_ID`. The selected tab must display the exact supplied URL. Login challenges are not bypassed. A failed login-dependent mapping is reported as blocked.

The final JSON contains the package path, CLI path, required environment, adapter digest, report, attempt count and passed-check count. Apply the values from that JSON in your shell, then call the generated CLI:

```bash
export APP2CLI_CDP=http://127.0.0.1:PORT       # result.json environment
export APP2CLI_TARGET=TARGET_ID              # result.json environment
export APP2CLI_HOME="$PWD/.local/state"
node .local/generate/dillinger/package/cli.mjs --schema
```

The concrete command names are generated by the agent and are listed by `--schema`. The output is a normal npm package; install its dependencies before moving it outside this checkout. REA and Codex are required during generation, not during ordinary generated-CLI execution.

Repeat the same live acceptance without spending another agent call, while the original application session is still open:

```bash
node bin/app2cli.mjs verify .local/generate/dillinger --out .local/verify/dillinger
```

This reruns the mutation, independent readback and restoration against the recorded adapter digest. It does not replace the earlier report.

## Run from an APK

```bash
export JAVA_HOME=/path/to/jdk
export REA_JADX_MCP_JAR=/path/to/jadx.jar
node bin/app2cli.mjs generate /path/to/application.apk \
  --id my-android-app --out .local/generate/android \
  --serial emulator-5554 --install
```

Use an authorized dedicated device/emulator. `--install` permits installing an absent package; an existing package with a different APK hash is rejected rather than replaced. With one authorized device, `--serial` can be omitted. `REA_ADB_PATH` selects the ADB executable. The runner discovers the package with REA, resolves its actual exported launcher via ADB, and gives the agent the real UI hierarchy. The agent can request additional REA class and method probes.

The Android generation path shares the same loop and contract. The unseen-application acceptance for this change is a Web run; it is not evidence that arbitrary APK generation works. The earlier Fossify Calculator sample remains separately runnable and tested.

## What a passed run establishes

The initial implementation supports a deliberately narrow `replace-value` test contract: read a value, replace it using the original app, observe the changed value, and restore the baseline. It does not claim to cover every operation of the application.

For Web, the runner chooses an unpredictable text marker. The agent must expose a read command, a mutation command, a baseline field, and a native DOM witness. A separate observer reloads the page and reads that witness directly; it never imports the generated adapter. The test also exercises a fresh CLI process, dry-run, deduplication, stale revisions and baseline restoration. Android uses a fresh native UI hierarchy and a scalar objective frozen across repair rounds. Android UI confirmation is not server confirmation.

The agent returns structured JSON strings for the manifest, source module and test plan. Codex runs in read-only mode while authoring; the runner writes the candidate files and launches real tests in separate processes. Generated adapters are executable local code and are not a security sandbox. Use a dedicated application session. Prompts explicitly treat captured page/source content as untrusted data.

The build's `runtimeVerified: false` remains a build-time statement. The separate digest-bound generation report records subsequent execution. A valid schema, a successful build, or an agent's assertion alone cannot produce a passed result.

The [Dillinger acceptance record](generation-acceptance.json) reports the clean generation run, repeat verification, isolated package installation, earlier development failures and a deliberately faulty negative control. To rerun that control against a completed test run:

```bash
node scripts/negative-generation-control.mjs .local/generate/dillinger .local/negative-dillinger
```

It creates a separate test copy whose dispatch does nothing and whose postcondition function lies. Success of the negative test requires the independent observer to reject that copy and confirm baseline restoration. The original generated adapter is untouched.

## Bounds and failures

- `--max-attempts` defaults to 4 and accepts 1–8 rounds. Read-only probes consume rounds too.
- `--agent-timeout` defaults to 600000 milliseconds per call and is bounded to 30 minutes.
- `--agent-model` and `--agent-effort` optionally select this run's Codex model and reasoning effort. Omit them to keep configured defaults. `--codex-ignore-config` skips the user Codex configuration for this invocation while still using its existing login; it can help isolate a broken custom provider/proxy. These options never edit global configuration. Invocation metadata is saved per attempt.
- CLI subprocesses, independent observations and REA analyses have separate time bounds.
- An existing output directory is rejected. Every run/attempt preserves its own evidence, candidate and raw subprocess outputs.
- A stopped run can continue with the same command plus `--resume`. The target and evidence hashes must match, and the run must have no restoration uncertainty. Prior attempts and the random challenge remain unchanged. Increase `--max-attempts` if its earlier budget was exhausted (maximum 8).
- Repair cannot change the frozen objective or lower the witness comparison. Failure to restore the baseline stops automatic mutations.
- Auth/provider failures, unavailable devices, mapping blockers and exhausted attempts return nonzero exit codes and retain a failure report. No automatic account/model switching occurs.
- A timed-out authoring call feeds its saved native trace into the next bounded attempt. Syntax checks run in the outer runner, not in agent-authored shell commands.

## Evidence and portability

REA's full CLI stdout is kept byte-for-byte, with SHA-256 and command metadata. `*.evidence.json`, `agent-summary.json`, DOM observations, capture projections, test reports and generation summaries are explicitly marked as project-created projections, not model-native or REA-native evidence.

REA 6.7.0 can return a browser script whose retained text fails its own declared digest. Such a source is quarantined from export; its original bytes and mismatch are retained privately. No digest or Evidence ID is rewritten to make it pass. REA exports the supported normalized capture format, whose lineage points back to the untouched stdout. Static analysis is bounded to a declared application slice; all verified exported sources remain available to the agent. This is not whole-application coverage.

On macOS, REA's Swift process helper requires a compatible installed SDK. If the current command-line tool SDK fails to compile the helper, explicitly select a compatible installed SDK with `SDKROOT` for the invocation. The generator does not change system-wide Xcode settings or disable process-ownership checks.

Keep `.local/` private. It can contain application content, source captures, agent traces, browser profiles, device details and execution journals. Only sanitized acceptance summaries should be committed. Do not upload an entire run directory to a public repository.
